# Plan 57・操作靈活性優化

2026-11-24，基準版本 `1.0.0-beta.89`。目標是讓玩家在換向、落地與收招時少一次補按，並能預判角色下一個動作。

## 本輪已修復

| 情境 | 現在的操作結果 |
| --- | --- |
| 面向右，同一步按左與攻擊 | 朝左出招。攻擊開始後，反向輸入仍須等到收招才能轉身。 |
| 普攻中排入重擊，再點普攻 | 優先嘗試已排入的技能，原本的 600 ms 有效期持續倒數。在可施放的第一步同時點普攻，重擊仍只施放一次。 |
| 按住上與右，從梯子側跳 | 離梯後，同方向持續攀爬會略過原梯 150 ms。期間仍能抓另一架梯；放開再按或改按反方向即可重新抓原梯。以基礎移速 140 px/s 側跳，150 ms 可移動約 21 px，足以離開原梯的 16 px 抓取範圍。 |

## 三項操作設計

以下保留三項實作的動機與驗收方式。三項均已接入遊戲，實玩結果見文末。

### 1. 讓急轉身跟隨最後按下的方向

目前左右同按會輸出零。從向右走改成向左走時，若左鍵比右鍵放開早一步，角色會停一下。先在 `KeyboardInputState` 記住最後按下的水平移動鍵，左右重疊時採用該方向。放開較新的鍵後，立即恢復仍按住的方向。

**驗收**　依序按住右、按住左、放開左、放開右，四次取樣應得到右、左、右、停止。交換左右並使用自訂鍵位再做一次。鍵盤自動重複事件不應搶回方向，失焦後則清空方向紀錄。

### 2. 讓收招前的跳躍能接上下一個動作

法師起手與盜賊攻擊鎖定期間，遊戲會清除當步的跳躍輸入。先試行在解鎖前最後 100 ms 接受一次跳躍，給快速點按和按住方向的玩家相同的接招機會。100 ms 是首輪試玩值，取自現有落地預輸入窗口。沿用現有跳躍判定，在可跳的第一步才起跳。

**驗收**　在平地分別用法師與盜賊，於解鎖前 50 ms 點跳應在解鎖後第一步起跳，提前 150 ms 點跳則應過期。試按兩次只起跳一次。期間若受擊、失焦、切圖或死亡，應清掉待執行的跳躍。另測按下加跳，避免穿平台的操作被轉成普通跳躍。

### 3. 讓點按普攻也能提前接下一擊

目前點按普攻若早於冷卻或收招結束就會被忽略。試行在兩者都將於 100 ms 內結束時暫存一次手動普攻。每次只排一擊，已排入的主動技能優先。這項調整只影響接收按鍵的時機，攻擊間隔仍由各職業的冷卻、起手與收招決定。

**驗收**　關閉連續普攻，在可出手前 50 ms 點一下，應於第一個可攻擊步驟打一擊；在同一窗口連點三次也只接一擊。接著排入重擊，確認重擊優先。最後開啟按住連續普攻，用相同時間長按，比對修改前後的攻擊次數及 MP 消耗。

## 試玩與採用條件

先做第 1 項，因為單靠輸入層便能驗證。第 2、3 項分開試玩，每項只調整一個時間窗口。以相同角色重複「急轉出招」「收招接跳」「普攻接技能」各十次，分別記錄需要補按和放手後意外出招的次數。補按減少、意外動作沒有增加，且對應驗收案例通過後，再採用該項調整。

## 2026-11-24 實作與試玩紀錄

水平移動採用最後按下的方向。跳躍與手動普攻各有 100 ms 預輸入窗口；普攻只暫存一擊，主動技能優先。法師依起手結束時間接跳，盜賊依整段攻擊結束時間接跳。下加跳維持穿平台語意。閃現成功位移後，已預按的普通跳躍會接在新落點。

在隔離的無頭 Chrome 中，分別從標題畫面建立相同路線的 Lv.1 法師，使用真正的方向鍵、Alt 與 Ctrl 在晨光營地操作。對照版本為已提交的 `de1b429`。每輪分開做換向、起手接跳與站定普攻接擊，以免空中的法師觸發站立施法限制。
