## 2. 目標與固定條件

**目標：正常遊玩大小能辨認角色動作與裝備，平台看起來屬於所在場景，各區材質有差異，戰鬥資訊清楚。**

- 延續使用者選定的失序司鐘者標準：清楚輪廓、體積、材質分區及乾淨透明邊；保留各角色身份與原有比例。
- 維持 1920×1080 畫布、960×540 邏輯視野、現有相機與角色顯示尺寸。沿用世界 nearest、Canvas FIT／UI 插畫 auto、世界文字 resolution 2；沒有新證據就不再做全域取樣比較。
- 保留 beta.62 的平台位置、上層守敵、首領選招、碰撞及攀爬範圍。美術裝飾不新增可站立面、不擋路、不形成掩體。
- 保留 B 版 HUD、羊皮紙選單、任務收合與鍵盤操作。已有 UI 驗收不列為本輪重做項目。
- 遊戲 ID、desktop 宣告、SDK、本機 key 與存檔讀 1–5／寫 5 均保持現況。
- 不預設重畫所有素材。先讀原稿與匯出鏈；有細節原稿就重新匯出，只有缺失部分才使用 ImageGen 編修。

## 3. 第一個交付批次：兩張地圖、兩套裝束

此批完成後先交付並停止擴展。第 4、5 節是後續路線，不在首批自動全部生成。

### W00：沿用基線與整理問題清單（小）

- 沿用 beta.62 配置圖與既有正常尺寸截圖，記錄候選版本、素材路徑及修改對象。
- 每個待改項目須能指出具體部位，例如「礦坑平台缺少支撐結構」或「鐵環甲攻擊中段手部輪廓不穩」；尚未檢視到的問題標為待確認。
- 輕革甲／鐵環甲先檢視完整攻擊序列，對照布衣已精修版本；檢視其餘狀態只為辨識重大差異，不預設全部重製。
- 本次規劃已檢視兩張既有 JPEG：beta.62 平台配置總覽、beta.60 營地正常畫面。總覽中的遠景拼接或形變只能列為觀察候選，須在正常相機重現後才當作缺陷。

交付：簡短的「素材／影格／問題／採用方法」清單。已有證據足夠時不為建立基線再啟動瀏覽器。

### W01：嫩芽林道、古礦入口的場景融合（中）

| 樣板 | 美術處理 | 遊戲內必須清楚的資訊 |
| --- | --- | --- |
| 嫩芽林道 | 在現有樹幹平台端部加入樹根、枝杈或藤蔓固定點；讓攀爬藤蔓與平台相接。變化集中在側面、下方，控制葉片密度 | 站立上緣、50px 平台缺口、藤蔓入口及上層蝸牛／史萊姆輪廓 |
| 古礦入口 | 棧台加入木柱、斜撐、鐵箍與梯頂固定件；支撐與地面接觸處補少量材質過渡 | 75／120px 高平台、55px 跳台缺口、魔像位置與上層哨兵；角色可穿過支架 |

實作方式：

1. 優先沿用現有平台／攀爬圖集，在獨立裝飾層補連接件。第一版最多新增兩張裝飾圖集，每張不超過 1024×1024；如需取代現有圖集，逐項說明原因。
2. 裝飾位置由現有 foothold／ladder 的 ID、端點及高度決定，固定選用變化；不依每次進圖隨機變動，不把美術位置寫進存檔。
3. 裝飾選材與 required assets 使用同一份映射，跟隨地圖建立／清除。只在現有 renderer 增加必要接線，不建立通用關卡編輯器或新物理系統。
4. 支撐、葉片與繩結置於角色及預警後方；不在平台跳躍缺口畫出看似可走的橫梁。裝飾不表現為會阻擋攻擊的牆面。
5. 地面接觸只做局部材質與透明邊過渡；首批不替換全世界地面或背景。

主要檔案：`src/render/terrain-style.ts`、`src/render/index.ts`、必要的 `src/app/assets.ts`、environment Manifest 及版本化 PNG。原 `src/content/world/maps.ts` 的玩法資料保持原值。

交付：兩張地圖的正常相機前後局部對照、新圖集及來源／匯出紀錄。

驗收：平台與場景有可理解的連接，落腳上緣及跳台缺口清楚；人物、血條、預警沒有被新增裝飾遮住；攀爬首尾與平台端點不變；進出地圖沒有殘留裝飾。

### W02：輕革甲、鐵環甲攻擊精修（中）

- 三套主角都已在 beta.59 重製，這次只補到布衣 beta.60 的第二輪動作品質；不重做整個角色。
- 先檢查每套六格攻擊，最多編修兩套共十二個攻擊影格；沒有具體問題的格沿用。優先處理臉型、髮型、手部、護甲邊界與光源一致性。
- 圖集維持 8×8、1536×1536、每格 192px，顯示框仍為 96×96。保留格序、動畫節拍、pivot、各姿勢錨點與原有武器／帽子疊圖契約。
- 保持未修改影格逐像素相同；每個改動影格按原姿勢核對身形與握點，不把所有姿勢強制對成相同外框。靜止定位及既有錨點偏差目標不超過 0.5 邏輯 px。
- 比較正常大小的左右向攻擊；暗色鐵甲與礦區同框時仍須能分辨手、劍、軀幹。
- 攀爬、受傷、死亡、增益若發現問題，記入下一批，不順帶展開整套動畫重製。

主要檔案：兩套角色的版本化 PNG、actors Manifest、`art-source/quality-pass2-20261105/` 原稿／prompt／匯出器。只有實際握點證據需要時才改 renderer／anchors。

交付：兩套攻擊序列前後對照、採用／未改影格清單、來源與逐格匯出報告。

驗收：連續攻擊不換臉、不忽大忽小，裝備左右向貼合，腳底與握點維持原定位；碰撞、傷害範圍及命中時機保持原值。

### W03：首批整合與收束（小）

- 合併 W01／W02 後才完成一次候選 build；中途未新增失敗證據就不重複 build 或已過檢查。
- 記錄每張新增／替換 PNG 的檔案大小、解碼量差值及場景新增 sprite 數；解碼估計不稱為瀏覽器記憶體峰值。
- 原有六種地形圖集與新裝飾分開，角色每張圖集可獨立回退。保留原稿及舊 runtime；成品清理另按實際引用決定，不在美術批次刪原稿。
- 交付採用結果、未採用項目、實際檢查與剩餘問題；候選版本在實作時同步更新 package／lock／game manifest。

首批的完成條件是兩張場景樣板及兩套裝束的採用結果已接入，直接相關檢查完成，未驗項目清楚列出。若 W00 證明某套裝束不需要編修，交付檢視理由即可，不為達到張數重畫。

## 4. 後續分區材質批次

`terrainStyle()` 目前只有 forest／ridge／mine 三套；其他有平台的十張地圖仍走通用平台／木梯。潮痕營站、誓鐘內殿、日井祭壇沒有高架平台或梯子，不為配齊主題新增地形。

| 批次／順序 | 適用地圖 | 平台／攀爬方向 | 新圖集上限 |
| --- | --- | --- | --- |
| B1 冰雪 | 雪痕海岸、霜松隘道；冰潮洞窟採冰洞變體 | 積雪岩棚＋覆霜繩梯；冰晶岩台＋掛霜鐵鏈。可站立線不可被厚雪掩蓋 | 兩套，共 4 張 |
| B2 沙海 | 琥珀砂岸、砂丘關道；日井盆地採古文明變體 | 風化砂岩／漂流木＋麻繩；日井雕紋石台＋青銅鏈。材質不只改色 | 兩套，共 4 張 |
| B3 遺跡 | 盤根石道、回聲長廊 | 盤根古石台＋粗根；雕紋石台＋古銅鏈。裂紋與裝飾不暗示假落腳面 | 兩套，共 4 張 |
| B4 營地／城鎮 | 晨光營地、木葉鎮 | 原木／木板平台＋木梯，以固定配件區分營地與城鎮 | 共用一套，共 2 張 |

每批先完成一張代表地圖，再套用同批其餘有相同需求的地圖。森林與紅岩已通過的基本拼接沿用；菌傘深林的大葉／菌菇差異在樣板風格穩定後，以局部變體處理。

統一圖集契約：

- 平台 5 格：左端／三款中段／右端，單格來源 128×96、邏輯 64×48，圖集 640×96。
- 攀爬 3 格：頂／中／尾，單格來源 64×64、邏輯 32×32，圖集 192×64。
- 站立線沿用平台上緣 inset 8；首尾裁切與中段原比例重複沿用現有 helper。
- 新圖均保留真透明、固定光源與邊緣規格。小裝飾放在站立線以外，不能擴大玩家認知的可站立範圍。
- 由 `terrainStyle()` 明確選材，未知主題保留 fallback；不要依背景名稱模糊匹配造成誤套。

本階段只替換外觀。新區域若也需要平台戰術重排，另列玩法設計、怪物位置及 focused tests，不能混入純畫質批次而沒有說明。

## 5. 背景、地面與戰鬥觀感的後續

### 場景層次（P2，中至大）

- 先選古礦入口做暗場樣板。目前它與赤岩山徑共用 `rock` 背景；可先用局部礦道結構與色調分離，再依正常畫面決定是否需要獨立背景。
- 依正常相機觀察中景樹幹、礦坑結構、地平線接縫及角色分離度。只有背景原稿不足才提高局部密度，不預設把所有背景放大。
- 後續地面可按雪／砂／遺跡加入相配表層；目前 renderer 的水平地面共用 `env:tile-ground`。改選材時必須同步 required keys，沿用接縫／overlap 與地面 y=600。
- 延續既有視差與底部錨定修正；天空與遠景保留柔和，主角、敵人、互動物及落腳線優先清楚。

### 戰鬥觀感（P1，集中補一次）

- beta.62 戰術邏輯已有 focused coverage；尚缺正常操作下的節奏與視覺確認。後續有實機測試要求時，取林道上層交戰、礦坑避攻／反擊、守衛平台震波／重擊三個短段即可。
- 同次需要時補兩把升級武器的左右向實際裝備，以及已學習重擊的真實施放；不以圖片載入／解碼冒充裝備與技能驗收。
- 先調整明確遮擋或透明邊問題。武器倍率、技能傷害、攻擊時間及首領難度保持現況。

## 6. 最少必要驗證與交付證據

本節保留規劃時的按需驗收設計；當時只有計畫文件。後續實作的實際結果以 [首批交接](reports/quality-pass2-20261105.md) 為準，不將下表全部視為已執行。

| 實際修改 | 必要檢查 | 範圍上限 |
| --- | --- | --- |
| 只替換角色圖格／Manifest | 匯出器核對 RGBA、透明邊、有效格、未改格及姿勢錨點；接入候選時做 content check／build | 不重跑整套世界或任務測試 |
| 新增主題選材／拼接或裝飾定位邏輯 | 更新 `src/render/terrain-style.test.ts` 的實際映射／位置案例；typecheck。新樣式加入後須調整「所有非 forest／rock 都是 fallback」的舊斷言 | 只跑受影響的測試檔；不增加模仿實作的測試 |
| 動畫／裝備錨點邏輯有改動 | 執行 `src/render/animation-contract.test.ts`、`tests/integration/app-hero-anchors.test.ts` 對應案例及 typecheck | 純 PNG 修改不自動擴成動畫系統回歸 |
| 純樣式／美術文案 | 審閱變更、必要素材預覽 | 不新增測試、不預設開瀏覽器 |
| 候選內容穩定 | 一次 `npm run check:content`、`npm run build`；所改文字檔的差異檢查 | 已過檢查僅在相關程式再次修改或出現新證據時重跑 |

後續若進行畫面驗收：

1. 使用 `headless:true`，沿用根 AGENTS 已驗證的一般使用者執行方式，建立新 session／profile／port／output；不重演已知受限 Chrome crashpad 失敗。
2. 主要尺寸為 1920×1080、頁面縮放 100%、DPR1，記錄實際 Canvas／CSS／相機資料。畫質判斷採正常遊玩相機，拉遠總覽只用於配置說明。
3. 第一批只看林道／礦入口，以及兩套裝束的左右攻擊；必要時增加同一畫面的 1280×720 縮小檢視。不預設每張地圖、每種尺寸都重新截圖。
4. 使用隔離 QA 進度並記錄來源，保留正式存檔；QA 前置任務或裝備不能算玩家實際完成流程。
5. 看 console／pageerror／失敗資源與新增裝飾的換圖清除。無可靠效能基線時不宣稱 FPS 改善或以固定百分比判定通過；只記錄明顯停頓／新增成本，問題出現才進一步量測。
6. 完整 PNG／原稿／長日誌保留工作區；AI 審圖每次 1–2 張必要 JPEG／局部裁圖，長邊 ≤1280、quality 60–75。透明素材先合成背景。

不為本批預設全套回歸、DPR2／4K、全世界流程、雲端帳號矩陣、iframe／全螢幕或發布驗收。環境問題若與修改無關，保存一次證據後停止擴大排查，交付時標明未驗範圍。
