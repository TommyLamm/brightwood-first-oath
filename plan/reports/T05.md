## 任務核心與呼叫契約

- `getQuestView(data, questId, catalog)`：回傳 locked／available／active／ready／claimed；kill/reach 讀 `QuestState.counters`，collect 讀目前背包，equip 讀物品定義所指定的裝備槽，reach 亦認 `visitedMaps`。未知任務 ID 會丟出 `RangeError`，不以假資料回退。
- `acceptQuest(data, questId, catalog)`：回傳 `Result<SaveData>`，驗證任務、前置與等級；僅建立新的 quests record 和 active counters，不改輸入。重複接取與已領取任務回明確錯誤。
- `recordQuestEvent(quests, event, world)`：`QuestEvent` 為 `{ type: 'reached'; mapId } | { type: 'killed'; monsterId }`。計數器以 objective `targetId` 為 key，只更新 active 任務且封頂目標數；擊殺事件去重由 app 的唯一 death event 負責。
- `planQuestClaim(data, questId, catalog)`：驗證 active/ready 與消耗物品足量，回傳 cloned `nextQuests`、`removeItems`、`reward`；不直接更改玩家、不領獎、不加 SP，也不改原存檔。

## 待接線與驗收界線

- T07 地圖載入：使用 `worldCatalog.maps` 與 `mapOrder`；進圖更新 location/visitedMaps 後，將 `reached` 事件送入任務核心。鎖定與生成仍由 app 使用 portal 的 `requiredQuestId`／`minLevel` 執行。
- T08 任務 UI：以 `getQuestView` 顯示狀態與 objectives；接取時提交 `acceptQuest` 的成功值；文字使用 quest 的 accept/progress/complete 欄位。回報 NPC 互動只提出領獎命令，不因播放文字直接標記 claimed。
- T14 主線／擊殺：只在唯一死亡事件送 `killed` 事件，並在符合 T01 `questDropByQuest` 且對應任務 active 時生成任務物品；一般怪物隨機 drops 不包含任務物品。
- T14 原子領獎：先取得 `planQuestClaim`；在玩家 clone 上依序套用 `removeItems`、`gainReward`、`setLevelFloor`、必要時 `changeJob`，全部成功才同時提交玩家和 `nextQuests`。q02 先補到 L10 再轉職。q08 的章節／首領 flags 亦應在成功提交後由 app 更新。
- NPC／怪物 `actorKey` 目前僅按 T10 asset spec 的 key 慣例驗證；`WorldCatalog` 沒有 asset manifest 欄位，T05 無法驗證實際資產檔存在。遊戲 runtime、場景可達性與 Playroom 發布仍待整合驗收。

### 戰鬥週期量級與判讀

為避免把玩家自由配點算成固定條件，採一個偏慢的示例：不分配 AP、不學技能，只用普攻；按任務獎勵換成的鐵劍／精鋼長劍，使用 08 的平均傷害式及 `basic.cooldownMs = 550`。這時角色攻擊值約為 starter-sword 31、iron-sword 39、steel-sword 51；按怪物 HP／防禦估算約需 815 次基本攻擊，攻擊間隔約 7.2 分鐘。這未包含任務目標回訪、受擊、喝水、操作介面、配裝或死亡；投入 STR／技能會縮短，低傷害遭遇更多敵招則會拉長。

#### 理論模型（非實測總時間）

理想跑圖下界 4.2 分鐘加上不投 AP、只用普攻的戰鬥週期示例約 7.2 分鐘，合計約 11.4 分鐘的模型動作量。這不是整段主線預測時間：合計排除了重複刷新後回訪、任務互動、敵人行動、喝水、配裝、死亡及其他玩家操作，也假定跨圖可無耗時互動。固定 8 秒重生是內容既有的機制，可能與走路／戰鬥重疊；本模型沒有把 88 秒重生週期額外相加，也沒有增加人為等待。

#### 實際總遊玩時間（未驗證）

本次沒有可玩的 T14 整合路線，因此實際通關時間仍未測量，不能報成 11.4 分鐘或其他確定時長。這份模型只顯示目前目標與地圖資料對 45–60 分鐘的支撐偏弱；玩家配點與技能會縮短戰鬥，實際追怪、出招、刷新回訪、死亡與 UI 操作則會拉長。08 是 T01/T05 的數值唯一來源，並要求以代表路線實測後集中調整；在缺少該實測時改任務數量，會以猜測偏離 08，也無從知道增加的目標是否把節奏推得過慢或過度重複。應等主 Agent 有可玩的 T14 版本後記錄分段時間，再按 08 決定是否增加有效戰鬥目標或調整曲線。本次沒有程式碼變更，故未執行本包測試。
