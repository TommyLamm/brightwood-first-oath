## 公開介面

```ts
createMonster(entityId: EntityId, spawn: MonsterSpawn, map: MapDef, rules: RulesCatalog): MonsterState

stepActors(
  monsters: readonly MonsterState[],
  player: CombatActor,
  map: MapDef,
  rules: RulesCatalog,
  dtSeconds: number,
  nowMs: number,
): ActorStep

applyMonsterHit(monsters: readonly MonsterState[], hit: Hit, nowMs: number): MonsterState[]
```

### 行為與接線

- `createMonster` 要求 spawnId/monsterId 已在當前 map 登記，並使用正式 `MonsterDef` 建立滿 HP、腳底位置、初始 idle/phase 1 狀態。沒有額外生成怪物或自產 EntityId。
- 普通怪使用 `enemy-melee`；guardian 初招 slam，之後在 slam/wave 間交替。guardian 上一招的 ID 留在 contract 既有 `pendingSkillId`，招式開始時存 origin/facing。AttackRequest 在 windup 起始幀只發一次；Telegraph 使用同一 SkillDef 的 reach/height 與 windup resolve 時間。普通怪冷卻讀 MonsterDef；首領依 08 在前招完整時長後再等 phase 1 的 2500ms 或 phase 2 的 1800ms。
- `applyMonsterHit` 只改命中怪物的 HP 與一般怪擊退；致死時設 `mode='dead'`、`deadAtMs` 並清除待攻擊快照。首領不受擊退。`stepActors` 對尚未回報的死怪只發一次 `deaths`；普通怪滿 8000ms 後發舊 EntityId 的一次 `respawnRequests` 並從回傳狀態移除；guardian 不重生。guardian HP 到或低於 maxHP 的 50% 時 phase 由 1 轉成 2，保持 phase 2。
- app 可在 AI 階段消費 request，使用當幀的怪物快照呼叫 T03，並在命中階段把 `Hit` 傳回本包：

```ts
const actorStep = stepActors(monsters, playerCombatActor, map, rulesCatalog, dtSeconds, nowMs);
monsters = actorStep.monsters;
for (const request of actorStep.attackRequests) {
  const proposal = tryAttack(combat, request, combatActors, rulesCatalog, nowMs, nextEntityId);
  if (proposal.ok) combat = proposal.value.state;
}
const combatStep = stepCombat(combat, combatActors, rulesCatalog, dtSeconds, nowMs, rng);
combat = combatStep.state;
for (const hit of combatStep.hits) monsters = applyMonsterHit(monsters, hit, nowMs);
for (const id of actorStep.deaths) grantDeathRewardAndRecordKillOnce(id);
for (const oldId of actorStep.respawnRequests) {
  const spawn = map.monsters.find((entry) => entry.spawnId === oldActorById.get(oldId)?.spawnId);
  if (spawn) monsters = [...monsters.filter((entry) => entry.id !== oldId),
    createMonster(nextEntityId(), spawn, map, rulesCatalog)];
  clearCombatAndHitIdsFor(oldId);
}
```

app 應按 T14 的單一固定 tick 排序，避免同一 `ActorStep` 的死亡事件在怪物受擊前消費。重試首領時以新 EntityId 呼叫 `createMonster`，並由 app 清除舊攻擊、命中集合與遭遇狀態。NPC 目前只有 `MapDef['npcs']` placement 與 `NpcDef`，契約沒有 NPC runtime actor 狀態或 T06 NPC 行為函式；本包因此不擴增第二套 NPC 型別或互動邏輯。
