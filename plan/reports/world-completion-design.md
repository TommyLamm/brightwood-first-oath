# Plan16 成長、經濟與司鐘者設計（W01）

日期：2026-10-27（香港時間）。狀態：**成長／經濟／首領數值與 W01-03 設計已交付；隔離 format5 候選可依 Plan16 實作，真實 format4 原件須經遊戲 UI 明確備份／升級確認後才遷移**。本報告只寫設計，不改遊戲程式、任務存檔、素材、版本或凍結成品。

## 適用決策

- 保持 Lv30、單人一轉劍士、現有技能／裝備欄及存檔身份；本期採 Lv30 後橫向進展，不加等級上限。
- 保留已領取任務、裝備、AP／SP、金幣與玩家旗標；不追發、不扣回、不重算歷史獎勵。`bossDefeated`／`chapterComplete` 繼續只表示第一章；其餘完成章節由對應主線任務 `claimed` 推導。
- 既有 45–80 秒是歷史的熟悉後命中至勝利比較範圍，不改寫為已達標。Plan15 高輸出樣本低於範圍，照實保留；此單一合法高輸出 rotation 的較快勝利不單獨構成平衡缺陷。60–120 秒初見參考是另一情境，該樣本不能判定其成敗。
- W05 完成定義以雙招有辨識度、預警能躲、一次可見轉場、勝／敗／重試／離場可靠、不跳過必要流程且普通合法配置補給可持續為主。沒有新的秒殺跳相、補給耗盡或其他具體失敗證據時，司鐘者保持現值，不重測同一 rotation、不追時間比例調 HP。

## Lv30 配置與實際傷害／MP

傷害計算採用現行公式：`floor((playerAttack × skillMultiplier × critMultiplier − bossDEF × 0.5) × variance)`；variance 是 0.95–1.05，crit multiplier 1.5。以下理論數是**非暴擊單次傷害**的整數邊界；不是實機全程 DPS。公式位置：[角色面板計算](../../src/domain/progression/index.ts)、[戰鬥傷害](../../src/domain/combat/index.ts)、[技能](../../src/content/rules/skills.ts)。

| 配置 | 真實／凍結依據 | 面對 Keeper DEF28 的攻擊 | MP 與生命／補給 |
| --- | --- | --- | --- |
| 普通第一章角色 | 正常角色 [q08 claimed format4 raw](../../output/playwright/resume-1515/q08-claimed-format4.json)：Lv30、STR157／DEX4、steel-sword ATK24、heavy10、sweep1、iron-mail／iron-helm；真實面板 HP712／MP86（上限98）。公式面板攻擊 341，crit 1.6%。 | heavy-strike10：乘數2.02，MP6，非暴擊約 **641–708**；sweep1：乘數0.80，MP10，非暴擊約 **245–271**。這份真實角色沒有 Keeper 命中樣本，以上只為規則推算。 | 大紅×9／大藍×9；大紅每瓶回200 HP、大藍每瓶回100 MP。未有此角色首領戰的實際耗用資料，不推估成已驗收。 |
| 高輸出首領樣本配置 | 冷凍 beta.18 正常 UI fixture [Boss measure](resume-boss-measure-20261026.md)：Lv30、STR128／DEX33、日井誓刃 ATK58、heavy10、sweep10、生命鍛鍊1、鐵環甲／鐵盔；面板攻擊346，crit13.2%、HP712／MP98。 | sweep10：乘數1.34，MP10，非暴擊約 **427–472**；實際校準畫面見 **457**，正式樣本首個命中畫面見 **452**。17 次 sweep 輸入後約17.968–18.684秒首次見勝利；這是該 rotation 的唯一樣本。heavy10：乘數2.02、MP6、非暴擊約 **650–719**；只是公式推算，未在該樣本測過。 | 起始 Q×10／W×5；正式樣本結束 Q×8／W×3、HP507／712、MP8／98。已確認消耗紅／藍各2瓶；未逐一驗證17個按鍵是否全部變成成功命中，不把輸入數直接乘成實際 MP 耗量。 |

這兩個配置的面板 ATK 接近（341 與346），主要差異是技能等級／DEX 暴擊率及武器；因此不可把普通玩家視為低傷、把日井誓刃當成唯一輸出差異。normal 的 heavy10 已足以造成高單發傷害；實際技能選擇會比武器差異更大。任何時長比較需記錄配置及 rotation，不能只看等級或單把武器。

## W01-03 存檔相容 gate

相容 owner 已交付 [world-completion-save-design.md](world-completion-save-design.md)。它靜態核對現行資料模型：quests/counters 可表達新增狀態，新 catalog 亦可驗證；缺少任務應維持未接取，接取時才建立目標 counter；不需新增 SaveData 欄位。但 beta.18 validator 依 current catalog 拒絕未知 q21／q22 ID，因此 format4「可序列化」不等於能與 beta.18 雙向相容。q22 的 basin reach 沿用 `visitedMaps` 推導，兩次甲蟲擊殺仍只記 active task 期間的事件。

該報告建議 format5、讀1–5／寫5，保持原有 payload 欄位、對本機 format4 首次升級前明確確認並備份。依 Plan16 與主代理調度，現在可先完成隔離候選、合成存檔檢查及 UI 備份升級流程；使用者在遊戲 UI 內確認備份／升級後才遷移其真實 format4 原件。正式雲端 format5 首寫仍須等相容版本正式可用、取得玩家明確確認與發布所需授權。**隔離程式實作不需另等聊天批准；真實資料遷移不是隱式授權。** 本包沒有跑 focused checks，也沒有觸碰真實存檔。

依該報告補上 format5 parser/writer、backup/confirmation 流程、strict validator/catalog allowlist、q21 inspect allowlist 及相符的舊檔保全與未知 ID 拒絕 focused tests。隔離候選可繼續整合 q21／q22；正式 format4 原件須經 UI 備份升級確認才改寫。不得放寬 validator、重設角色、改 q08 旗標、降寫 format4 或假定宣告格式就代表相容。

## 最小實作與驗收範圍

1. W03／W04 只增加上表任務和必要 UI，保持 q01–q20、一次性現有獎勵、Lv30、藥價及裝備不變；q21／q22 的 claim 需在手動回報後才給獎勵。
2. 直接驗 q21：q09 claimed 才可接、未 active 不記 counter、marker inspect 一次、回報一次給 500 金及指定補給、不阻擋 q10/q11。
3. 直接驗 q22：q13 claimed 才可接、active 後 reach basin＋擊退兩甲蟲、不要求甲殼、手動回報只給一次、不阻擋 q14/q15；滿袋保持 ready 並可整理後 claim。
4. 按[相容方案](world-completion-save-design.md)以自有隔離資料跑缺新任務舊檔、安全備份／升級／重讀及 counter 保留的 focused checks；不以 fixture 覆蓋[正常 q08 raw](../../output/playwright/resume-1515/q08-claimed-format4.json)。UI 真實升級流程只在玩家明確確認後改寫其原件。
5. W05 只補欠的實際音訊聆聽與改動所需的有限首領驗收；本包沒有跑 browser、tests、build、package 或改 frozen beta.18。

本報告與相容 owner 的靜態報告一起構成 W01 設計交付；隔離候選可進入實作／驗收，真實存檔遷移仍須玩家在遊戲 UI 明確確認備份升級。
