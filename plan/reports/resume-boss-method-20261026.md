# 首領計時方法靜態審查（2026-10-26）

## 判定

上次樣本證明的是：從誓鐘內殿入口開始，固定向右按住 6,500 ms，之後不再水平修正，按 80,005 ms 上限跑完仍未看到勝利 UI。它不證明「有效攻擊持續 80 秒仍打不贏」：正式迴圈只讀玩家 HP／MP／藥水和可見勝負結果，沒有記錄首領 HP 或逐次命中；T0 還包含接近路程。首個接近後讀值是玩家 655/712，終點 236/712、MP 2/98，代表角色受傷且樣本右截斷，不能證明玩家有打中首領，也不能推定首領擊殺時長或平衡問題。（`formal-run.js`: 36–45、120–124、144–170；`overnight-boss-timing-20261026.md`: 5、22–25）

具體操作缺口是把一次固定接近當成已校準站位，之後 38 輪沒有依畫面修正距離／方向，也沒有確認首領血條變化。Ctrl 是單次按鍵事件，不是按住連發；該腳本每輪按住 550 ms 仍只發一次普通攻擊，1／2 也按 MP 門檻才施放。（`formal-run.js`: 144–170、231）

## 源碼支持的距離判斷（僅對目前 checkout 的 source）

| 項目 | 值與來源 |
|---|---|
| 玩家／首領出生點 | x=160／x=1200，同一 y=600；首領身體 88×76。`src/content/world/maps.ts:276–285`、`src/content/rules/monsters.ts:102–105` |
| 玩家移動與身體 | 140 px/s，24×44。未受干擾的 6.5 秒直走是 x≈1070；這只是理想估算。`src/content/rules/progression.ts:9–16` |
| 玩家攻擊 reach | 普攻 65、重斬 85、橫掃 110。`src/content/rules/skills.ts:4–20` |
| 首領攻擊 reach | 垂鐘重擊 180、低鳴橫掃 360。`src/content/rules/skills.ts:112–123` |

判定用朝向矩形與目標身體是否重疊（`src/domain/combat/index.ts:192–202`）。若玩家在 x=1070、朝右，而首領仍在 x=1200，首領左身體邊是 x=1156：普攻終點 1135、重斬 1155，兩者都差一點未命中；橫掃終點 1180 可命中。反過來首領朝左時，180／360 的攻擊可覆蓋玩家。這證明該固定座標下「首領能打到、部分玩家攻擊打不到」確實可能；但不能當成上次樣本的實際站位結論，因司鐘者會在未進入當前招式距離時以 38 px/s 追近，受擊亦會擊退玩家，兩者都會改變座標。（`src/domain/actors/index.ts:412–441,466–493`；`src/app/gameplay.ts:308–323`）

因此要先看到角色面向首領、同一地面線且距離合適，再談攻擊輸出。攻擊會保存起手朝向；UI 畫面看不到方向或未出現首領受擊提示時，應以短方向鍵修正，而不是加傷害／改 HP。（`src/domain/combat/index.ts:47–69,192–202`）

## 一次正常 UI 有界樣本建議

- 以「繼續冒險」後可見的 712 HP／98 MP 為起點，維持舊口徑：T0 記第一次右移；另記 T_hit 為第一次在首領身上看到傷害數字且綠色首領血條縮短的影格。不要把入口到命中混成 hit-to-win 時長。
- 在同一個正常 UI 操作批次內，以 150–250 ms 的右移短按接近；看見同高、面向首領後，Ctrl／1／2 各用一次正常點按。只有當畫面顯示角色被推開或首領已越過角色時，才短按相反方向修正。命中以畫面傷害數字及血條減少確認；維持距離以後續截圖中的兩個角色相對位置確認。只讀可見 HP／MP／藥水，不讀私有 runtime state。
- 單次樣本從 T0 最多跑 80 秒；每約 10 秒留一張 UI 影格，並在首次確認命中及勝負終點留影。看到勝利／重試 UI 時立刻記 T1 並結束；若到 80 秒無勝利，標成右截斷，不填擊殺時間、不報 PASS。每次取樣維持在同一 run-code 批次，避免工具呼叫間角色繼續 idle 受擊。
- 批次結尾先保存可見終點，再在 `finally` 釋放所有可能按住的方向、Ctrl、1、2、Q、W；若仍在遊戲中則立即按 Esc 暫停後才返回工具。勝利／死亡 UI 已終止戰鬥時記錄終點並釋放按鍵，不再等待下一輪。（現有腳本已有 key-up／Escape 清理：`formal-run.js:209–214`。）

既有 q18 分支報告記載短接近後以普通近戰最終擊敗首領，並取得勝利 UI；這支持一般輸入流程可完成，不提供本次 fixture 的擊殺秒數。該成功分支是 beta.15；上次計時是 beta.17，而本次讀到的是目前 source。尚未比對 frozen beta.18 bundle，故上述距離推論只作 source 條件判斷，不能直接代替 beta.18 驗收。（`ruins-d-browser-branches-retry.md:26–30`；`overnight-boss-timing-20261026.md:9`）
