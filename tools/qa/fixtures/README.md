# Synthetic portal fixture

This directory holds an immutable, synthetic format 5 camp/right save used only as an isolated QA precondition. The fixture is a byte-for-byte copy of the historically accepted file. Its expected size is 616 bytes and its SHA-256 is `4e55c8c1a8ef4c1078c46be6de7ff28b19cb10b132278761dfe3fe82e7c6fb00`. See [provenance](portal-camp-right-format5.provenance.json).

## Use only in a newly isolated QA run

Use this data only when a browser run is independently needed and the portal case requires this synthetic precondition. For the later harness work, follow Plan18 C02 and the applicable QA lifecycle and overlay procedures.

1. Create a new run directory, browser profile, and game origin. Confirm the requested candidate manifest has ID `brightwood-first-oath` and the intended version before starting the seed step.
2. Pass this fixture explicitly to the new run harness and verify its SHA-256 before listening or seeding. If the fixture is missing or the hash differs, stop before either action. Do not fall back to the beta22 output directory.
3. Require the canonical localStorage key `brightwood-first-oath:save:v1` to be `null` on that new game origin. If it has any value, stop; never clear, replace, or seed over it. Seed this fixture once only.
4. Preserve the run's before and after raw exports. Keep the profile, origin, and outputs isolated from real player data.
5. Normal Continue and one Space press after seeding can show the synthetic portal precondition and its existing gate message. This does not demonstrate normal NPC travel, portal transfer, task completion, account saves, or cloud-save behavior.

Never seed this fixture into a real player's save, an existing browser profile, or any origin with an existing canonical value. Do not copy it into `public/`, a candidate `dist/`, or a release package. Do not edit this file; a genuinely different QA precondition needs a new filename and its own provenance.

The original beta22 source and all historical QA evidence remain preserved. This copy does not change the save key, save format, runtime, candidate version, or game progress. Current project status is linked from [plan/status.md](../../../plan/status.md#current-state).
